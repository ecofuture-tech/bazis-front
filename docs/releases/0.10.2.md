# bazis-front 0.10.2

A patch of 0.10.1, from a run of an agent that built a product of bookings with lines: a
boolean of a payload that could not be sent as false, a key of a create form of a dashboard
whose hint named only the schema, and a table of a list wider than a desktop that `shots` did
not warn of. It requires `bazis>=2.17.0`, as 0.10.1 did; the format of the contract stays 11.

## Fixed

- **A boolean without a default is sent as false when its checkbox is left unchecked.** The
  checkbox of a boolean (`FieldInput`) showed false unchecked, but the form had no value for
  it until the user clicked it, and sent none: a required boolean (`is_intact: bool` of a
  payload, a `BooleanField` without a default on a create) was refused with 422 "required" at
  a checkbox that the user saw unchecked, and a scenario that fills it with `false` could not
  pass. The value of a boolean without choices and without a default is false from the start
  (`startValue` of `@/bazis/react`): the payload of a transit, the body of a custom action (its
  dialog, its form) and a create form (`useResourceForm` sends it like a change of the user)
  send what the checkbox shows; a create form sends false of every such boolean of the schema,
  also of one that it does not show (give that one a default). Its checkbox is no longer
  `required` and has no asterisk: a required checkbox asks to be checked, and false is an
  answer. An update form is unchanged: it starts with the value of the item.

## Changed

- **The hint of a key that a mapping of the specs does not take names the keys that it
  takes** (S002, P002, D002, D003; not of the groups of the tokens, whose keys are free, nor
  of a mapping of alternatives, a link or a group of the navigation, a form of a create or of
  an action, whose closest alternative may not be the meant one): `filters`
  of a create form of a dashboard was told only the schema to follow, as `requires` was before
  0.10.1. `filters` there has a hint of its own: the pickers of a create form of a dashboard
  offer every item (the backend validates the value); a create action of the list of the entity
  or a form screen narrows them.
- **V021** (warning) of `shots`: the table of a list scrolls sideways at the width of a desktop,
  its last columns (often the status) out of sight; the message names the columns of its first
  row beyond its edge. Give the list fewer `columns`; the others are in its card.
- The guide: `startValue`, the boolean of a create form, the rows of P002, S002, D002, D003 and V021.

## Upgrading

```bash
pip install -U bazis-front
python manage.py bazis_front update      # react, resource, transit-bar, screens, bazis/shots.ts
python manage.py bazis_front shots       # V021 of the tables of the lists wider than a desktop
```

A model or a payload that was given a default only so that its boolean could be sent
(`is_intact: bool = True`) may drop it after `update`: unchecked is now false.
