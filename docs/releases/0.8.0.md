# bazis-front 0.8.0

The checks of the specs stop teaching the same mistakes twice (a decimal of a payload, a
text with a colon, a summary in two languages, the users without a route), and the visual
check logs in on a cold server. The format of the contract stays 10: no product needs to
export the contract again, `manage.py bazis_front update` brings the copies.

## Features

- **P036** (warning): `packages` has `users`, the contract has no route of the user
  resource (`capabilities.users.user_resource`, `users.user`), and a field relates to it (the
  author of a status, `status_author`, of a model with a workflow; an assignee): the users
  that a screen shows are labeled by the start of their id. A product with `users` and
  neither a workflow nor such a field has no P036.
  Register the user route set of the project (`users/routes.py`, the team), see the guide
  "The users that the pickers offer".
- **The summary of the product is a text or the text in each language**
  (`summary: {en: ..., ru: ...}` in `spec/product.yaml`). It is not a text of the
  interface: it is shown nowhere and `check` does not compare it with `languages` (no S027
  for a summary in one language).
- **The top bar splits its row by links, not by entries.** A group of links is shared by the
  row and the menu `nav:more`: its first links stay in the row under its heading, the others
  are in the menu under the same heading. A role whose links do not all fit (for example
  "Board" and "Rejected" of a group "Workshop" next to the public screens) sees its working
  screens in the row, not behind More.

## Changes

- **P017 takes a decimal as a string or a number.** A decimal of pydantic is `anyOf:
  [number, string]` in the contract: the spec may declare it `string` (as the field of an
  entity, P013) or `number`; it was `number` only, so the hint sent the agents to the type
  they had to change again. Only this union is compared with both members; any other union
  (an integer or a string, a URL or the empty string) is typed by its first member, as
  before. The hint about the decimal is given for a decimal only.
- **A payload field that is a `$ref` is typed by what it refers to.** An `Enum` or a
  `Literal` (`{enum, type: string}`) is `string`, a model is `json`; P017 took every
  `$ref` for an object, so an enum was declared `json`.
- **P001 and S001 tell what to do with a text with a colon.** A YAML text with `: `
  (`summary: Workshop "Spitsa": sign up`, also inside `{ru: ...}`) is read as a mapping:
  the hint says that it goes in quotes.
- **The visual check waits 15 s for the login.** `loginAs` of the helpers of the
  end-to-end tests waits for the logout or the error of the login for `LOGIN_WAIT = 15 s`
  (it was the 5 s of `expect`): the first login of a run warms the dev server of Vite. The
  test of `playwright.shots.config.ts` has 60 s.
- **The header of the top bar is as wide as the window** (it is no longer limited by
  `max-w-6xl`, the horizontal padding is kept), so its row of links uses the real width. The content of the screens stays
  within `max-w-6xl`, at the center. `data-nav-entry` of the hidden copy of the row is on the
  links only (the group has none); it is an internal mark, not a contract of the tests.

## Upgrading

```bash
pip install -U bazis-front
python manage.py bazis_front update      # the helpers of the end-to-end tests, the config of the shots, the schemas of the specs
python manage.py bazis_front check
```

1. `update` merges `playwright.shots.config.ts` and `e2e/bazis/index.ts`; a product that
   changed them keeps its changes in the merge.
2. A product with `packages: [users]`, a field related to the users and a project that does
   not route them now has P036
   (a warning, `check` still exits with 0): register the route set of the users, export the
   contract again (`bazis_front contract`).
3. A payload field declared `number` or `string` for a decimal needs no change. A payload
   field of an `Enum` or a `Literal` declared `json` (what P017 asked for before) is now
   reported by P017 after the update: declare it `string`.
4. `bazis_front update` takes the new `app-shell.tsx` of the components. A product that
   changed `app-shell.tsx` by hand gets a 3-way merge: conflicts are expected at `measureRow`,
   `TopNavigation` and the container of the header (`max-w-6xl`); resolve in favor of the new
   code and carry the local changes over. The contract needs no export again. A product with
   `navigation: topbar` shows more links in the row at wide windows and its header now spans
   the window; check the screenshots after the update. A `sidebar` product
   is not changed.
