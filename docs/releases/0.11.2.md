# bazis-front 0.11.2

A patch of 0.11.1, from a product of rentals whose guests read its roles: the guide and the
hint of S061 told a picker of the users of a role to register the router of bazis-permit,
which makes the roles public. It requires `bazis>=2.17.0`, as 0.11.1 did; the format of the
contract stays 12.

## Fixed

- **A picker of the users of a role no longer makes the roles public.** A filter through the
  roles (`roles__slug: manager`) needs a route set of the roles in the contract, and the guide
  and the hint of S061 gave `bazis.contrib.permit.router`, whose route set is a public catalog:
  a guest read the slugs and the names of the roles (`GET /api/v1/permit/role/` without a
  token, 200). The guide ("The users that the pickers offer") now gives the route set of the
  app `users/` for the signed-in users only,
  `class RoleRouteSet(UserRequiredRouteBase, RoleRoute)` registered in `users/router.py`
  (401 for a guest), as the rules of bazis-mcp 2.14.1 do, and never the router of
  bazis-permit, the id of a role (not portable between databases) or a `get_queryset` of the
  users (it narrows every picker of the users). The hint of S061 sends to that section; S061
  is unchanged.

## Upgrading

```bash
pip install -U bazis-front
```

A product that registered `bazis.contrib.permit.router` for the picker of a role replaces it
with that route set in `users/routes.py` and `users/router.py`, then exports the contract
again (`python manage.py bazis_front contract`): the resource `permit.role` keeps its type and
its fields, so the specs and the screens are unchanged.
