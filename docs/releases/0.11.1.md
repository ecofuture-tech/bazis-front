# bazis-front 0.11.1

A patch of 0.11.0, from a run of an agent that built a product of rentals with photos: the
thumbnail of a card broken in the dev server when its list had read the photo, a sum that a
scenario could not expect as the card shows it, and a scenario that creates an item with a
unique name, which failed at its second run. It requires `bazis>=2.17.0`, as 0.11.0 did; the
format of the contract stays 12.

## Fixed

- **The thumbnail of a file already read is no longer broken in the dev server.**
  `useDownloadUrl` made the object URL of the content in the render (`useMemo`) and revoked it
  in the cleanup of an effect: `StrictMode` (the dev server of every product) mounts a
  component twice, and the second mount kept the URL that the first unmount had revoked. A
  content read before (the thumbnail of a list, then that of its card, `display: image`) has
  its URL in the first render, so the card showed a broken image in the dev server and in the
  screenshots of `shots`; the built frontend was not affected. The URL is now made as the
  component mounts and kept while a mounted component shows the content
  (`useSyncExternalStore`, one URL for the components that show the same content), revoked when
  none does.

## Added

- **`{run}`, the text of the run of a test, in the texts of the scenarios**: an item with a
  unique field (a name, a code) that a scenario creates takes it in that field,
  `fill: {name: 'Tent {run}'}`, and the steps after find and expect it by it,
  `where: {name: 'Tent {run}'}`, `values: {name: 'Tent {run}'}`. The helpers of the end-to-end
  tests replace it in a `fill`, a payload, a `where` and `values` with the start of the test
  in base 36, the same in all its sessions and another at every run, so that the scenario
  passes again on the database that keeps the items of the previous runs. A `where` or
  `values` with `{run}` before a `fill` or a payload gave one is P022: no item has it.

## Changed

- The guide: `{run}` among the rules of the scenarios that run again; the texts of
  `expectValues` as the card shows them in the language of the tests (a sum with
  `display: {currency: RUB}` is `1 500,00 ₽`, a decimal without `display` its digits,
  `1500.00`), a run of spaces of either side compared as one space (the no-break spaces of the
  groups of digits of `Intl` too, as Playwright compares them; now tested); the row of P022.

## Upgrading

```bash
pip install -U bazis-front
python manage.py bazis_front update      # react (useDownloadUrl), e2e/bazis/ ({run})
```

A scenario that deletes the item it creates only so that its next run can create it again
(or a test of `e2e/custom/` that cleans it up) may give the unique field `{run}` instead.
